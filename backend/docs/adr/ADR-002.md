# ADR-002 — `BaseModel` inclui apenas `UUIDMixin` + `TimestampMixin`

**Status:** Aceito
**Módulos envolvidos:** 2.4 (ORM)

## Contexto

A especificação do Módulo 2.4 pedia que `BaseModel` desse suporte a
identificador único, timestamps, soft delete, versionamento e auditoria
— sugerindo uma única classe base cobrindo tudo isso.

## Decisão

`BaseModel` (`app/models/base_model.py`) combina apenas `UUIDMixin` +
`TimestampMixin`. `SoftDeleteMixin`, `VersionMixin` e `AuditMixin`
existem como mixins independentes (`app/models/mixins.py`), compostos à
la carte pela entidade concreta que precisar deles.

## Justificativa

Forçar todo mixin dentro de uma `BaseModel` única violaria Interface
Segregation (SOLID, princípio obrigatório do próprio módulo) — uma
entidade que nunca precisará de soft delete não deveria carregar a
coluna `deleted_at` só por herdar de uma base monolítica. A própria
especificação do módulo também exige explicitamente que os mixins sejam
"independentes e reutilizáveis", o que uma `BaseModel` que já os
incorpora todos contradiria na prática.

## Impacto

Toda entidade de domínio futura declara explicitamente quais mixins
precisa: `class Documento(BaseModel, SoftDeleteMixin): ...`. Isso é uma
linha a mais por entidade, em troca de nunca ter uma coluna morta
(nunca lida, nunca escrita) numa tabela real.

## Alternativas consideradas

- **`BaseModel` com todos os mixins incluídos**: era a leitura mais
  literal da especificação — descartada pelo motivo acima.
- **Nenhuma `BaseModel`, só mixins soltos**: descartada porque
  `UUIDMixin` + `TimestampMixin` juntos são o caso comum o suficiente
  (praticamente toda entidade) para justificar uma base própria, evitando
  repetir os dois mixins em toda declaração de entidade.
