# ADR-004 — `ValidationException` é irmã de `APIException`, não subclasse

**Status:** Aceito
**Módulos envolvidos:** 2.5 (APIs REST), 2.7 (Tratamento Global de Erros)

## Contexto

No Módulo 2.5, `ValidationException` era uma subclasse de `APIException`
(`app.core.exceptions`). A especificação do Módulo 2.7 define a
hierarquia oficial de exceções com `ValidationException` como irmã
direta de `APIException`, ambas sob `PIAOSException` — não uma
subcategoria de `APIException`.

## Decisão

Adotada a hierarquia da especificação do Módulo 2.7:
`ValidationException` herda diretamente de `PIAOSException`, não de
`APIException`.

## Justificativa

Semanticamente, "erro de validação" e "erro de requisição HTTP genérico"
são categorias irmãs, não uma subcategoria da outra — um erro de
validação de domínio (levantado manualmente, não pelo Pydantic) não é
necessariamente um "erro de API" no mesmo sentido que um 404 ou um 400
genérico são. Manter a hierarquia pedida pela especificação mais recente
evita uma divergência silenciosa entre o código e a documentação oficial
do projeto.

## Impacto

Um teste existente (`test_exception_hierarchy`, Módulo 2.5) verificava
`issubclass(ValidationException, APIException)` — passou a falhar e foi
atualizado para refletir a hierarquia correta. **O comportamento HTTP
observável não mudou**: mesmo status 422, mesma mensagem, mesmo formato
de resposta — só a relação de herança em Python.

## Alternativas consideradas

- **Manter `ValidationException` como subclasse de `APIException`** (não
  quebrar o teste existente): descartada — divergiria da hierarquia
  oficial que a própria especificação do Módulo 2.7 define, criando uma
  incoerência entre código e documentação mais prejudicial que ajustar
  um teste.
